- **RF-6** Only pytest tells an assertion failure from a collection error by exit code (1 versus 2). Every other runner exits the same way for both, so red's right reason has to come from output markers. Per runner (a "probe" means the runner was run on a throwaway test, not read in docs):
  - pytest: exit 1 = tests failed, 2 = collection error (probe), 4 = usage or conftest import error; markers "ERROR collecting", "ImportError while importing test module", "error(s) during collection";
  - python -m unittest: exit 1 for both; an assertion counts under `failures=`, an import error under `errors=` with "Failed to import test module";
  - jest: exit 1 for both; marker "Test suite failed to run" (probe);
  - vitest: exit 1 for both; marker "Failed Suites" (probe);
  - mocha: the exit code is the failure count, so it can't separate them; marker "Exception during run" (probe);
  - go test: exit 1 for both; markers "[build failed]" and "[setup failed]"; with `-json`, the `FailedBuild` field;
  - cargo test: exit 101 for both; markers "error[E" and "error: could not compile" (probe);
  - rspec: exit 1 for both unless the project sets `error_exit_code`; marker "error(s) occurred outside of examples";
  - JUnit via Maven or Gradle: exit 1 for both; markers "COMPILATION ERROR" (Maven) and "Execution failed for task ':compileTestJava'" (Gradle), from forums, not official docs.
