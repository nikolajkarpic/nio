## Source: https://github.com/nikolajkarpic/nio/issues/128

## Problem
Measured over the three efforts run on 2026-11-08 (#123, #49, #122; 309 transcripts, list-price estimates as in `.nio/research/2026-11-06-speedup.md`):
- Orchestration (main sessions + their general-purpose driver agents) was **~76% of ~\$616**. Jurors were 15%, workers 3%.
- One driver on #49 ran 5½ h, 590 turns at a **432k average context**, ~\$177 (29% of the day). The explainer and full-auto main sessions ran 570 and 496 turns at 290k and 261k.
- Every turn re-reads everything the effort has done so far: earlier gates, tasks and findings.

## Proposal
- A driver lives for one unit of work: one gate, or one epic (its tasks plus its implementation jury).
- It starts from a short brief: `nio flow next` output, the handoff state, and the rules it needs. It ends with a short summary (what closed, what's open, the next command).
- The main session only routes. It never reads packs, juror outputs or test logs itself.
- The skills (`implement`, `jury`) say this as host-neutral instructions, with the Claude Code subagent as an optional way to do it.

## Open questions
- Is the unit a gate, an epic, or a token budget (restart when context passes N)?
- Is the brief generated by `nio` (e.g. `nio flow brief <slug>`) or written by the outgoing driver?

## Source: https://github.com/nikolajkarpic/nio/issues/85

## Problem
On Claude Code, a foreground tool call is moved to the background after about 3 minutes, so `nio flow green`, `nio jury evidence` and suite runs each needed a wait loop by the orchestrator (faster-checks effort, PR #81). That costs orchestrator turns (#76).

## Proposal
The implement and jury skills say up front: start long commands in the background and wait for completion, no polling. Revisit once #72/#73 make most runs short.

### Comment on #85 (2026-11-14)

More data from 2026-11-08 (#123, #49, #122): about 90 `sleep`/`until` wait loops, roughly 4½ h in total. Each wake-up re-read the waiting agent's whole context (up to 432k tokens). Wall-time cost is small (the waits were for real work), but the token cost is not.
Proposal (one of four fixes picked from this analysis): the skills tell the orchestrator to run long `nio` commands and subagents in the background and wait for the completion notification, never a sleep loop. Where a host has no notifications, one blocking wait with a timeout, never a poll.
