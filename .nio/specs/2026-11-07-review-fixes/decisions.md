# Decisions: 2026-11-07-review-fixes

The choices this effort made, for #101 to #104. Grill answers were given under the human's standing delegation (grill.md Q1 to Q6); jury rounds refined two of them (plan gate J-1/J-13, J-2/J-14).

| Decision | Options considered | Chosen | Why | Consequence |
| --- | --- | --- | --- | --- |
| How the jury knows a refuter file is genuine (#101) | 1. The gate ledger records each refuter batch's IDs (`asked[run]`) in the call that shows the batch; a refuter file counts only in a run with a batch, and only for its IDs. 2. Accept the file only when `packs/refuter.md` exists and is older than it. 3. A host hook that limits each juror's Write to its own output file. | 1 | Only `nio` writes the ledger, at the moment the batch is shown: `refuter_pack` (called by `nio jury next` exactly when it shows the batch) and `nio jury collect` (which prints it). A pack file and its mtime are as forgeable as the refuter file. A hook is per host (Codex has none). | A refuter file in a run with no batch stops the step: "refuter output before its batch ... delete it and call again". Blocks for IDs outside the batch are ignored; the first verdict per ID counts. A run in flight across the upgrade has its refuter re-run. A juror that forges the ledger itself is not stopped (option 3, left in #101). |
| Whether jurors may change what they judge (#101) | 1. Refuse new lens outputs when the judged version recorded in `packs/step.json` differs from the version now. 2. Snapshot `git status`/`HEAD` when jurors start; refuse on any change outside the run's jury folder. 3. Nothing. | 1 | A few lines on a value the step already records. Option 2 trips on everything legitimate that writes between steps (ledger, verdict records, evidence, other work in the tree). | An edited spec, plan or tasks file, or a new epic commit, while its jurors ran stops the step: "the <gate> changed after <run>'s packs were written: restore it, or start a new run". Edits elsewhere (a peer's output file, unrelated code) are not caught. |
| Overwriting a peer's output and reading it early (#101) | 1. Leave it in #101 for the host write guard. 2. Fix it here. | 1 | Needs a per-host write guard; not minimal. | #101 stays open for the guard; this PR closes the two paths that let a juror approve a gate. |
| Bytes for wave patches (#102) | 1. `records.git(..., raw=True)` returns stdout as bytes; `land` and `shelve` write with `write_bytes`. 2. Decode everything with `surrogateescape` and keep text. | 1 | No newline translation and no codec on the patch path; every other caller keeps today's text mode. (A worker first did 2 for all callers; sent back.) | Patches are byte-identical to `git diff --binary`. Three older test fakes of `records.git` forward `**kw` (change request C-261107-bff2, accepted under delegation). |
| A rerun with no lens to re-check (#103) | 1. Never print "run each juror" with none listed: end with `next: show the human`. 2. Re-run every lens that voted when the artefact changed but no lens has a fix to check. 3. Both. | 3 | 2 gives the common case (risk accepted, wording touched) a real check instead of a human close; 1 is the guard when nothing a lens could see changed (whitespace only). | No loop at any gate. 2 applies at the spec, plan and tasks gates after a rejected round; the implementation gate keeps its conformance-only re-run. The guard creates no run folder. |
| #104 item 1: `test_pack.py -v` | 1. selfcheck skips words starting with `-`. 2. Drop `-v`. | 1 | One line; keeps the documented flag. | `-v` works again. |
| #104 item 2: misuse tests on a self-check suite | 1. Leave in #104. 2. Derive a per-test command from the suite's per-file prefix. | 1 | Needs a parser for the suite's prefix and a rule for which runners take test names: a design call, not a small fix. | Misuse tests on this repo's suite stay "attack not run". |
| #104 item 3: covered journeys skip `Expected:` | 1. Leave in #104. 2. Count a journey covered only when every step's Expected is empty. | 1 | Every quickstart step has an Expected, so 2 would turn off the covered-journey speed-up from #81 and change its test; matching against the suite's own output is a larger change. | A covered journey still passes on the suite's exit code. |
