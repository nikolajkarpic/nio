# Research: 2026-10-28-plan-jury

Facts the grill looked up instead of asking.

- **RF-1** The jury skill is what runs a gate: it plans with `nio jury plan`, starts the lenses and the refuter, and applies dispositions. Today it says only the spec gate is built. The plan skill ends by sending the human to the plan jury. Source: skills/jury/SKILL.md:11: "The spec gate is the only gate so far; the plan and tasks gates come with their stages."; skills/plan/SKILL.md:112: "Then say the next stage is the plan jury."
- **RF-2** Issue #57 and its research comment are the evidence for the journey. No reviewed tool has an automatic plan reviewer. Its traps include the author reviewing its own plan and reviewing only `plan.md`. Source: https://github.com/nikolajkarpic/nio/issues/57#issuecomment-6466810047: "no tool has an automatic reviewer for the plan"
- **RF-3** The security card has no `## At plan` section, only `## At spec`. The jury skill passes a lens only the current gate's section, so at the plan gate security would get no questions. Source: src/nio/agents/security.md:23: "## At spec"; https://github.com/nikolajkarpic/nio/issues/47: "The jury skill passes only the current gate's section."
- **RF-4** A change request is a `change` record with `against` naming the spec, plan or record that is wrong. Writing one stops the work it blocks and tells the human. Nothing reopens an approved gate for it. The fix-check pack (`nio jury fixcheck`) already holds only the items changed since the last judged version, plus their neighbours. Source: skills/remember/SKILL.md:98-100: "For a change request, set `against` to the spec, plan or record that is wrong … stop the work it blocks"; src/nio/jury.py:240-242: "since the version the last round judged."
- **RF-5** `nio check plan` already checks the following for free. Every contract cites FRs that exist. Every contract is delivered by exactly one build-order entry. Every FR has a contract, and every AC has a test at the AC's level. A test's `Covers:` names real contracts. Bindings match the code (new or existing). A new folder or new stored data with `architecture: none` stops the plan. Every journey has a scenario. Source: src/nio/plan.py:220-222: "every FR is served, every AC tested, every journey walked"; src/nio/plan.py:298-299: "isn't in any `{key}:` line"
- **RF-6** #47 decided the plan gate's triggered lenses: logic when contracts carry state, risk and rollback on migration, schema change, data deletion or deploy config, and security. Source: https://github.com/nikolajkarpic/nio/issues/47: "risk and rollback (plan): migration, schema change, data deletion, deploy config"; "logic (plan): contracts with state"
- **RF-7** `nio jury plan` already blocks a gate when a lens it needs has no card, and names the missing card. Source: src/nio/jury.py:186: "missing cards: {', '.join(missing)} — the gate is blocked until they exist"
- **RF-8** A gate's ledger path is built from the gate's name, so the plan gate's ledger is `jury/plan.json`, next to the spec gate's `jury/spec.json`. Source: src/nio/jury.py:34: "path = folder(root, slug) / f\"{gate}.json\""
- **RF-9** The approved tasks-stage spec already counts a gate the human closed as approved, and a gate handed to the human but not closed as not approved. It decided this for the spec gate. Source: .nio/specs/2026-10-27-tasks-stage/spec.md:205: "a gate handed to the human but not closed by them does not count."
- **RF-10** `nio jury plan` reads only the spec, its risk flags, the agent cards and the config, and calls no model. Issue #57 decided that the `Like:` line's existence is checked for free. Source: src/nio/jury.py:157-187 (`plan` reads `spec.check`, `records.parse`, `agents.load` and `records.config` only); https://github.com/nikolajkarpic/nio/issues/57#issuecomment-6467006369: "`nio check plan` confirms that code exists, for free"
