- **RF-1** Across all efforts' history files, 34 jury gates were passed by the human. The median gap from the previous history line to that pass is 6 minutes, and the longest is 64 minutes: each gate waited on the human. Source: .nio/specs/*/history.jsonl: `"kind": "pass", ... "who": {"role": "human"`.
- **RF-2** `nio check spec` accepts `[human]`, `[default]`, `[agent]`, `[research: RF-n]`, `[derived: <IDs>]` and `[deferred: DF-n]`, and not `[auto]`. Source: src/nio/spec.py:36: `TAGS = "[human], [default], [agent], [research: RF-n], [derived: <IDs>] or [deferred: DF-n]"`.
- **RF-3** No skill says how to wait on commands the host moves to the background. Issue #85 is still open and proposes adding that wording to the implement and jury skills; today the orchestrator improvises a wait loop. Source: issue #85: "each needed a wait loop by the orchestrator … The implement and jury skills say up front: start long commands in the background".
- **RF-4** Spec, plan and tasks approval commits land on the current branch (main here). Implementation runs on `nio/<slug>`, and closing the last epic prints `merge: nio/<slug>`. Pull requests are opened by hand with `gh`. Sources: src/nio/implement.py:198: `return f"nio/{slug}"`; src/nio/flow.py:1097: `[f"merge: {implement.branch(slug)}"] * last`; git log: `86c45e6 nio: approve spec` on main.
- **RF-5** The flow lock is held only for the length of one writing call and taken over once it is a minute old with its process gone, so nothing stops a second driver between calls. `state.json` keeps the current run in `run`. Source: src/nio/flow.py:198: "Hold `.nio/specs/<slug>/flow.lock` for the body"; flow.py:27 `STATE_KEYS = (... "run")`.
